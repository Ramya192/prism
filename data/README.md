# data/

Sample documents for testing Prism outside the running app — for example,
downloading these directly from the repo instead of using the UI's own
"try a sample file" pickers, or testing the upload widgets with files that
aren't already wired into `streamlit_app.py`.

Each domain folder has two sets:

1. **The same files the UI's own sample pickers use** (copied here as-is,
   not regenerated) — `AC00003_statement.pdf` (Banking), `CLM001_claim.pdf`
   (Insurance), `WALLET001_statement.pdf` (Financial Services),
   `EMP001_payslip.pdf` (Payroll & HR), plus Banking's
   `transactions_balanced.csv`. Source of truth for these stays wherever
   the app itself reads them from (`domains/<domain>/.../data/...`) — the
   copies here are just a convenience, not a second source of truth.

2. **A second, independent set** — one PDF, one DOCX, and one bulk CSV per
   domain, deliberately different content (new account/claim/wallet/
   employee IDs, different transactions and figures) from set 1, so you
   have real files to test with that aren't already in any UI dropdown.
   Generated by `generate_additional_samples.py`:

   ```
   python data/generate_additional_samples.py
   ```

   The PDF and DOCX in each domain hold the same content (proves both
   loader paths); the CSV is a separate multi-row file in that domain's
   real Tier 1 schema (see `core/domain_classifier_agent.py`'s
   `CSV_SCHEMA_HINTS`), not just the PDF/DOCX reformatted.

| Domain | Set 1 (matches UI) | Set 2 (new, distinct) |
|---|---|---|
| Banking | `AC00003_statement.pdf`, `transactions_balanced.csv` | `AC00777_statement.{pdf,docx}`, `AC00777_transactions_bulk.csv` |
| Insurance | `CLM001_claim.pdf` | `CLM900_claim.{pdf,docx}`, `CLM900_claims_bulk.csv` |
| Financial Services | `WALLET001_statement.pdf` | `WALLET900_statement.{pdf,docx}`, `WALLET900_transactions_bulk.csv` |
| Payroll & HR | `EMP001_payslip.pdf` | `EMP900_payslip.{pdf,docx}`, `EMP900_payroll_register_bulk.csv` |
